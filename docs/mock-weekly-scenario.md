# weekly mock 데이터 시나리오 설명 (팀 공유용)

수신 서버·대시보드 개발과 QA에 쓰는 **일주일치 mock 데이터**가 어떤 상황을
가정한 것인지 정리한 문서다. 생성·전송 방법은 [mock-sqs-guide.md](mock-sqs-guide.md) 참고.

## 한 줄 요약

> **명동역 인근 전광판 1대가 일주일(월~일)을 정상 운영한 기록.**
> 매일 06~24시, 5초마다 1건씩 총 90,720건. 평범한 평일 + 비 오는 날 하루 + 주말 이벤트 하나.

집계 단위는 "지역 전체 유동인구"가 아니라 **보드 앞 보도 한 지점을 지나간 사람**이다.

## 1. 규모 — 일주일 통행량

| 날짜 | 요일 | 통행자(OTS) | 응시자(LTS) | 응시율 | 비고 |
|---|---|---:|---:|---:|---|
| 07-13 | 월 | 14,107 | 662 | 4.7% | |
| 07-14 | 화 | 14,047 | 628 | 4.5% | |
| 07-15 | 수 | 9,995 | 267 | 2.7% | **우천** |
| 07-16 | 목 | 14,112 | 618 | 4.4% | |
| 07-17 | 금 | 16,750 | 802 | 4.8% | 저녁 피크 연장 |
| 07-18 | 토 | 17,332 | 854 | 4.9% | **19시 이벤트** |
| 07-19 | 일 | 12,302 | 639 | 5.2% | |
| **합계** | | **98,646** | **4,470** | **4.5%** | 90,720건 |

평일 하루 약 14,000명 = **시간당 약 790명 = 2.3초에 1명**이 보드 앞을 지나간다.
피크 시간대(18시)는 시간당 1,170명 = 3초에 1명.

요일마다 값이 다르고 평일끼리도 조금씩 어긋나는데(14,047~14,112), 이는 요일 배율과
푸아송 노이즈가 겹친 결과다. **매일 같은 값이 나오지 않는 것이 의도된 동작이다.**

금요일은 저녁 피크가 밤늦게까지 이어지고, 주말은 출근 피크 없이 오후~저녁 단봉이다.
00~06시는 미운영이라 **메시지가 아예 없다**(데이터 공백 처리 확인용).

## 3. 응시(LTS)와 시청 시간

응시율은 시간대에 따라 달라진다. 바쁜 출근길엔 낮고 여유로운 저녁엔 높다.

| 시간대 | 응시율 |
|---|---|
| 06~10시 (출근) | 2~4% |
| 10~17시 (낮) | 3~6% |
| 17~24시 (저녁) | 4~7% |

응시 지속시간(dwell) 분포는 **짧은 글랜스가 대다수**다:

| 1~2초 | 2~3초 | 3~4초 | 4초 이상 |
|---:|---:|---:|---:|
| 51.0% | 24.5% | 11.9% | 12.5% |

> **응시율 4.5%가 낮아 보일 수 있다.** 업계에서 흔히 말하는 주목률 30~50%와는
> 지표 정의가 다르다. 우리 수치는 "카메라에 잡힌 **전체 통행자**(등 돌린 사람,
> 반대편 인도 포함) 중 보드를 **1초 이상 실제로 응시**한 사람"이라 분모가 훨씬 넓고
> 판정이 엄격하다. 모델링·서베이 기반 추정이 아니라 실측이라 부풀림이 없다는 점이
> 오히려 강점이다. 외부 공유 시 이 정의를 반드시 함께 설명할 것.

## 4. 인구통계 — 명동 상권 구성

명동은 성격이 다른 두 집단이 겹치는 상권이라 세그먼트를 나눠 합성했다.

- **내국인 직장인**: 40~50대 편중
- **외국인 관광객**: 20~30대·여성 편중

혼합 비율은 시간대별로 달라진다 (평일 업무시간엔 직장인, 저녁·주말엔 관광객 우세).
결과 분포는 다음과 같다.

**성비** (검출 성공 기준): 남 44.3% / 여 55.7%

**연령대**

| 10세 미만 | 10대 | 20대 | 30대 | 40대 | 50대 | 60대+ |
|---:|---:|---:|---:|---:|---:|---:|
| 1.0% | 5.2% | 23.9% | 21.7% | 22.7% | 19.2% | 6.4% |

20~40대가 68%를 차지하되, 관광 상권 특성상 50대 비중(19%)도 낮지 않다.
전체 통행자의 약 15%는 **성별 미상**으로 집계된다(얼굴 미검출·측면 통과 등).

## 5. 데이터에 심어둔 이벤트

정상 패턴만 있으면 대시보드의 이상 탐지·예외 처리를 검증할 수 없어 두 가지를 넣었다.

**① 수요일 — 비 오는 날**

통행량은 0.7배로 완만히 줄지만, **우산이 얼굴을 가려 검출 품질이 더 크게 떨어진다**:

| 항목 | 평일 | 우천 수요일 |
|---|---:|---:|
| 통행자 | 14,100명 | 9,995명 (−29%) |
| 응시율 | 4.5% | **2.7%** (−40%) |
| 성별 미상 | 15% | **30%** (2배) |

즉 "통행 감소폭보다 응시·인구통계 결측이 더 크게 무너지는" 형태다. 단순 통행량
감소와 구분해서 보여줄 수 있는지 확인하는 케이스.

**② 토요일 19:00~19:30 — 근처 행사**

30분간 통행량이 2배로 튄다. 짧은 스파이크를 그래프가 뭉개지 않고 잡아내는지,
이상치 알림이 오작동하지 않는지 확인하는 케이스.

## 6. 어디까지가 실측이고 어디부터가 가정인가

외부 공유나 광고주 대응 시 **가장 중요한 구분**이다.

**실측 근거가 있는 값** — `data/jsonl` attention 세션 27개(총 175분) 분석

| 항목 | 실측치 | 반영 방식 |
|---|---|---|
| 통행량 | 낮(09~15시) 평균 1.07명/5초 | 곡선의 낮 시간대가 이 값과 **1.0배로 일치**하도록 역산 |
| 응시율 | 자연 관찰 세션 1.8~6.3% | 시간대별 2~7% 범위로 반영 |
| dwell | 중앙값 1.5~2.2초, p90 4.4~6.3초 | 로그정규(중앙값 2초)로 재현 |

**가정에 해당하는 값** (실측 없음, 상식·업계 통념 기반)

- **출퇴근·심야 시간대 곡선** — 실측 촬영이 전부 09~15시라 그 밖 시간대는 근거 없음
- **요일 배율, 우천 효과, 이벤트 스파이크**
- **성비·연령 분포** — 명동 상권 통계를 참고했으나 **출처 재확인 필요**
  (`mock_sqs/demographics.py` 주석의 인용 수치는 아직 검증되지 않음)

> 통행량을 **실측 최고치가 아니라 실측 평균에 맞춰** 앵커링한 점이 중요하다.
> 이전 버전은 최고치 기준이라 하루 33,000명이 나왔는데, 자체 실측 평균의 2.4배라
> 방어가 어려웠다. 현재 값은 자체 데이터와 모순이 없다.

## 7. 데이터 받는 방법

```bash
# 파일로 받기 (전송 없음, 압축 1.0MB)
python main.py --mock-sqs --scenario weekly --seed 42 --out weekly.jsonl.gz

# SQS로 직접 적재
python main.py --mock-sqs --scenario weekly --seed 42
```

- `--seed` 가 같으면 **언제든 같은 데이터가 재현**된다 (버그 재현·회귀 테스트용)
- 파일 형식은 JSONL(한 줄에 메시지 1건). 전송하는 값과 완전히 동일하며
  건별로 JSON Schema 검증을 통과한 것만 저장·전송된다
- 메시지 식별자는 기존에 쓰던 값 그대로다 (`board_gangnam_01` / `adscope-cam-01`).
  통행 패턴과 인구통계만 명동 상권을 모델링했고 보드 ID는 바꾸지 않았으므로,
  수신 측에서 이미 등록해 둔 보드로 그대로 들어온다
